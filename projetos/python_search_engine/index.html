Python Search Engine

Python CLI Information Retrieval BM25 Inverted Index pickle NLP

O Python Search Engine é um motor de busca handmade em Python, construído do zero com armazenamento local e interface de linha de comando. Implementa um índice invertido binário serializado com pickle e o algoritmo de ranqueamento BM25 para indexar e recuperar documentos de texto (.txt) — sem dependências de motores externos (Lucene, Elasticsearch, etc). The Python Search Engine is a handmade search engine in Python, built from scratch with local storage and a command-line interface. It implements a binary inverted index serialized with pickle and the BM25 ranking algorithm to index and retrieve text documents (.txt) — with no external engine dependencies (Lucene, Elasticsearch, etc).

Layout do armazenamentoStorage layout

.search_data/
  docs/
    <doc_id>.txt
  index/
    inverted_index.pkl
    meta.json

Cada documento adicionado recebe um doc_id sequencial e é copiado para docs/. O índice invertido (inverted_index.pkl) mapeia termos → postings e fica serializado em binário; metadados (estatísticas de coleção, comprimento médio de documento, etc) ficam em meta.json. Each document gets a sequential doc_id and is copied into docs/. The inverted index (inverted_index.pkl) maps terms → postings and is serialized in binary; collection metadata (statistics, average document length, etc) lives in meta.json.

Como funciona internamenteHow it works internally

Quando um documento é adicionado, o texto é tokenizado, stopwords são removidas e cada termo é registrado no índice invertido (estrutura que mapeia termo → lista de (doc_id, frequência, ...)). A estrutura é serializada em binário com pickle, o que torna a leitura e escrita extremamente rápidas em comparação a formatos textuais como JSON. When a document is added, the text is tokenized, stopwords are removed, and each term is registered in the inverted index (a structure that maps term → list of (doc_id, frequency, ...)). The structure is serialized in binary with pickle, which makes reads and writes far faster than text-based formats like JSON.

Durante a busca, o algoritmo BM25 calcula um score de relevância para cada documento que contém termos da query, ponderando: (i) a frequência do termo no documento (TF saturada), (ii) a raridade do termo na coleção (IDF) e (iii) o comprimento do documento relativo à média (normalização). Os top-k documentos com maior score são retornados. During search, the BM25 algorithm computes a relevance score for each document containing query terms, weighting: (i) term frequency in the document (saturated TF), (ii) term rarity across the collection (IDF), and (iii) document length relative to the collection average (length normalization). The top-k documents with highest scores are returned.

MotivaçãoMotivation

Este projeto foi desenvolvido para estudar, na prática, os fundamentos de Recuperação de Informação. Construir um motor de busca do zero é a forma mais direta de internalizar como funcionam a tokenização, a construção do índice invertido e a matemática por trás de algoritmos clássicos de ranqueamento como o BM25 — coisas que normalmente ficam escondidas atrás da API de motores prontos. A escolha por pickle ao invés de JSON foi deliberada: o objetivo era também experimentar serialização binária e o trade-off de velocidade × portabilidade. This project was built to study the fundamentals of Information Retrieval hands-on. Building a search engine from scratch is the most direct way to internalize how tokenization, inverted index construction, and the math behind classic ranking algorithms like BM25 actually work — things normally hidden behind a high-level search engine API. The choice of pickle over JSON was deliberate: part of the goal was experimenting with binary serialization and its speed × portability trade-off.
